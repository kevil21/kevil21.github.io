problem: Enterprises deploying fleets of AI agents had no shared, multi-tenant view of how those agents behaved, cost and failed in production.
approach:
  - Customer agents emit OTLP traces from inside their own infrastructure; a per-tenant telemetry exporter forwards them.
  - Postgres staging buffers raw OpenTelemetry spans before normalisation.
  - Azure Data Explorer is the source of truth — fact tables, dimensions and 31 materialized views.
  - An ADX → Elasticsearch sync function fans the materialized views into per-tenant Elasticsearch indices every 10 minutes.
  - A FastAPI gateway fronts Elasticsearch, Kibana, Cosmos DB, LiteLLM and the insights engine with JWKS-validated auth.
  - A Next.js 16 / React 19 frontend on the Shidoka design system delivers KPI tiles, embedded Kibana pages, chat and agent-trust views.

A360 is a set of microservices that ingest OpenTelemetry traces from customer-deployed agents, normalise
them into Azure Data Explorer, project them into Elasticsearch for dashboarding and surface them through a
Next.js frontend behind a FastAPI gateway. Kevil is the lead developer; he owns the ADX → Elasticsearch
sync service, the synthetic telemetry generator and large parts of the frontend.

Internal repository names, database naming patterns and infrastructure sizing published on earlier
versions of the site are deliberately not reproduced here.
